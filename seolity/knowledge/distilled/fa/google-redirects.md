# ریدایرکت‌ها و جستجوی گوگل

این راهنما توضیح می‌دهد چه زمانی و با چه روشی باید آدرس‌ها را ریدایرکت کرد و گوگل هر نوع ریدایرکت را چگونه تفسیر می‌کند. انتخاب درست نوع ریدایرکت (دائمی یا موقت) و روش پیاده‌سازی تعیین می‌کند کدام آدرس در نتایج جستجو نمایش داده شود.

## موارد استفاده از ریدایرکت

- هنگام انتقال سایت به دامنه جدید از ریدایرکت استفاده کن تا انتقال تا حد امکان روان انجام شود.
- اگر یک صفحه از چند آدرس مختلف در دسترس است (مثلاً https://example.com/home، http://home.example.com یا https://www.example.com)، یکی را به‌عنوان آدرس اصلی (canonical) انتخاب کن و بقیه را به آن ریدایرکت کن.
- هنگام ادغام دو وب‌سایت، لینک‌های آدرس‌های قدیمی را به صفحات متناظر درست ریدایرکت کن.
- اگر صفحه‌ای را حذف کرده‌ای و می‌خواهی کاربران را به صفحه‌ای جدید بفرستی، از ریدایرکت استفاده کن.
- اگر از پلتفرمی مانند Blogger یا Shopify استفاده می‌کنی، ابتدا بررسی کن راهکار ریدایرکت داخلی دارد یا نه و از راهنمای همان پلتفرم استفاده کن.

## انتخاب بین ریدایرکت دائمی و موقت

- نوع ریدایرکت را بر اساس مدت اعتبار آن و صفحه‌ای که می‌خواهی در نتایج جستجو نمایش داده شود انتخاب کن.
- از ریدایرکت دائمی فقط وقتی استفاده کن که مطمئنی بعداً برگردانده نمی‌شود؛ چون گوگل آن را سیگنالی می‌داند که مقصد باید canonical باشد و مقصد جدید در نتایج نمایش داده می‌شود.
- از ریدایرکت موقت برای وضعیت‌های کوتاه‌مدت استفاده کن؛ در این حالت صفحه مبدأ در نتایج باقی می‌ماند و گوگل مقصد را canonical نمی‌داند (هرچند اگر سیگنال‌های canonical دیگری وجود داشته باشد، مقصد ممکن است همچنان ایندکس شود).
- اگر سرویسی موقتاً در دسترس نیست، با ریدایرکت موقت کاربران را به صفحه‌ای توضیحی بفرست تا آدرس اصلی در نتایج جستجو آسیب نبیند.
- کدهای 301 و 308 دائمی‌اند؛ کدهای 302، 303 و 307 موقت‌اند.

## ریدایرکت‌های سمت سرور (روش ارجح)

- برای تغییر آدرس صفحه در نتایج جستجو، تا حد ممکن از ریدایرکت دائمی سمت سرور (301 یا 308) استفاده کن؛ زیرا بیشترین احتمال تفسیر درست توسط گوگل را دارد.
- در PHP هدرها را با تابع header() و پیش از ارسال هر خروجی تنظیم کن و بعد از آن exit() را صدا بزن؛ برای دائمی از 'HTTP/1.1 301 Moved Permanently' و برای موقت از 'HTTP/1.1 302 Found' همراه با هدر Location استفاده کن.
- در Apache برای ریدایرکت ساده از mod_alias (Redirect permanent یا Redirect temp) و برای حالت‌های پیچیده‌تر از mod_rewrite با RewriteRule و فلگ [R=301] یا [R] استفاده کن.
- در NGINX از return 301 یا return 302 برای حالت ساده و از rewrite همراه با permanent یا redirect برای حالت پیچیده استفاده کن.
- برای سایر وب‌سرورها (مثلاً LiteSpeed) به راهنمای همان سرور یا پشتیبانی هاستینگ مراجعه کن.

## meta refresh و معادل HTTP آن

- فقط وقتی ریدایرکت سمت سرور ممکن نیست، از meta refresh به‌عنوان جایگزین استفاده کن.
- برای ریدایرکت دائمی از meta refresh فوری (0 ثانیه) استفاده کن؛ گوگل آن را دائمی تفسیر می‌کند.
- اگر meta refresh با تأخیر بیش از 0 ثانیه تنظیم شود، گوگل آن را موقت تفسیر می‌کند؛ پس برای انتقال دائمی از تأخیر استفاده نکن.
- تگ meta refresh را در عنصر <head> قرار بده (مثلاً <meta http-equiv="refresh" content="0; url=https://example.com/newlocation">) یا با کد سمت سرور از هدر HTTP به‌صورت Refresh: 0; url=... استفاده کن.

## ریدایرکت‌های JavaScript

- فقط وقتی ریدایرکت سمت سرور یا meta refresh ممکن نیست از ریدایرکت JavaScript استفاده کن.
- بدان که گوگل ریدایرکت JavaScript را پس از خزش و از طریق Web Rendering Service اجرا می‌کند و اگر رندر ناموفق باشد، ممکن است ریدایرکت را هرگز نبیند.
- برای پیاده‌سازی، مقدار window.location.href را به آدرس مقصد در یک بلوک script داخل head تنظیم کن.

## ریدایرکت‌های crypto

- اگر هیچ روش دیگری ممکن نیست، دست‌کم با یک لینک به صفحه جدید همراه با توضیح کوتاه (مثلاً «به سایت جدید منتقل شدیم») کاربران را راهنمایی کن.
- برای اطلاع‌رسانی انتقال محتوا به موتورهای جستجو به ریدایرکت crypto تکیه نکن، مگر اینکه چاره دیگری نداشته باشی؛ همه موتورهای جستجو آن را ریدایرکت رسمی نمی‌شناسند.
- پیش از رو آوردن به ریدایرکت crypto، از ارائه‌دهنده هاستینگ برای پیاده‌سازی روش‌های دیگر کمک بگیر.

## نام‌های جایگزین آدرس پس از ریدایرکت

- بدان که گوگل پس از ریدایرکت هر دو آدرس مبدأ و مقصد را ردیابی می‌کند؛ یکی canonical می‌شود (بسته به سیگنال‌هایی مانند دائمی یا موقت بودن) و دیگری به نام جایگزین (alternate name) تبدیل می‌شود.
- اگر بعد از انتقال دامنه گاهی آدرس‌های قدیمی هنوز در نتایج دیده شدند نگران نشو؛ این رفتار عادی است، چون ممکن است پرس‌وجوی کاربر نشان دهد آدرس قدیمی را بیشتر قبول دارد.
- منتظر بمان تا با عادت کردن کاربران به دامنه جدید، نام‌های جایگزین بدون اقدام اضافی از نتایج کم‌رنگ شوند.
