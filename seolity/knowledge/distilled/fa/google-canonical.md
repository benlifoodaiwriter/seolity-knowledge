# مشخص‌کردن URL کانونیکال با rel="canonical" و روش‌های دیگر

این راهنما توضیح می‌دهد چگونه برای صفحه‌های تکراری یا بسیار مشابه، URL کانونیکال را با ریدایرکت، rel="canonical" و نقشه سایت به گوگل اعلام کنیم. رعایت این اصول سیگنال‌ها را روی یک URL متمرکز می‌کند، پیگیری معیارها را ساده‌تر می‌کند و از هدررفتن زمان خزش روی نسخه‌های تکراری جلوگیری می‌کند.

## انتخاب روش و اولویت سیگنال‌ها

- برای اعلام URL کانونیکال از روش‌های زیر به ترتیب قدرت تأثیر استفاده کن: ریدایرکت (سیگنال قوی)، برچسب rel="canonical" (سیگنال قوی) و قرار دادن URL در نقشه سایت (سیگنال ضعیف). این روش‌ها روی هم اثر تجمعی دارند و ترکیبشان شانس نمایش URL دلخواه را بالا می‌برد.
- تعیین کانونیکال اجباری نیست؛ اگر آن را مشخص نکنی گوگل خودش بهترین نسخه را انتخاب می‌کند. با این حال برای کنترل بیشتر، آن را صریحاً اعلام کن.
- اگر از سیستم مدیریت محتوا مانند WordPress استفاده می‌کنی و به HTML دسترسی مستقیم نداری، تنظیمات سئو یا افزونه‌های CMS را برای تنظیم عنصر canonical در بخش <head> بررسی کن.

## دلایل مشخص‌کردن کانونیکال

- کانونیکال را تعیین کن تا URL مورد نظرت در نتایج جستجو نمایش داده شود، مثلاً صفحه محصول تمیز به‌جای URL دارای پارامتر ردیابی مانند gclid.
- برای یکپارچه‌سازی سیگنال‌ها (مثل لینک‌های ورودی از سایت‌های دیگر) روی یک URL ترجیحی، نسخه‌های تکراری را به آن کانونیکال کن.
- برای ساده‌تر شدن پیگیری معیارهای یک محتوا، از چندین URL مختلف برای همان محتوا پرهیز کن.
- برای جلوگیری از هدررفت بودجه خزش روی نسخه‌های تکراری، کانونیکال را اعلام کن تا Googlebot بیشتر روی صفحه‌های جدید یا به‌روزشده وقت بگذارد.

## رعایت اصول کلی و اشتباهات رایج

- از robots.txt برای کانونیکال‌سازی استفاده نکن، چون گوگل ممکن است URLهای مسدودشده را بدون محتوا همچنان ایندکس کند.
- از ابزار حذف URL برای کانونیکال‌سازی استفاده نکن، چون همه نسخه‌های آن URL را از نتایج جستجو پنهان می‌کند.
- برای یک صفحه، با روش‌های مختلف URLهای کانونیکال متفاوت اعلام نکن؛ مثلاً در نقشه سایت یک URL و در rel="canonical" URL دیگر.
- fragment (بخش بعد از #) را به‌عنوان URL کانونیکال تعیین نکن، چون گوگل عموماً از آن پشتیبانی نمی‌کند.
- روی خود صفحه کانونیکال هم یک rel="canonical" خودارجاع (self-referential) قرار بده.
- برای جلوگیری از انتخاب نسخه کانونیکال در یک سایت از noindex استفاده نکن، چون صفحه را کاملاً از جستجو حذف می‌کند؛ راه‌حل ترجیحی rel="canonical" است.
- در لینک‌دهی داخلی همیشه به URL کانونیکال لینک بده، نه به نسخه تکراری، تا ترجیحت برای گوگل روشن‌تر شود.

## پیاده‌سازی rel="canonical"

- عنصر <link rel="canonical" href="..." /> را در بخش <head> صفحه‌های تکراری قرار بده و به صفحه کانونیکال اشاره بده. این عنصر فقط در <head> پذیرفته می‌شود، پس مطمئن شو دست‌کم بخش head دارای HTML معتبر است.
- از URL مطلق (مثل https://www.example.com/dresses/green/green-dress.html) استفاده کن، نه مسیر نسبی؛ مسیر نسبی ممکن است در بلندمدت مشکل ایجاد کند، مثلاً اگر سایت تست به‌طور ناخواسته خزیده شود.
- برای فایل‌های غیر HTML مانند PDF از هدر HTTP به شکل Link: <URL>; rel="canonical" استفاده کن و در آن هم URL مطلق بنویس. این روش فقط برای نتایج جستجوی وب پشتیبانی می‌شود.
- فقط یکی از دو روش (عنصر HTML یا هدر HTTP) را انتخاب کن؛ استفاده هم‌زمان از هر دو احتمال خطا و ناسازگاری URLها را بالا می‌برد.
- از rel="canonical" همراه با ویژگی‌های hreflang، lang، media یا type برای نسخه‌های جایگزین استفاده نکن، چون برای کانونیکال‌سازی نادیده گرفته می‌شوند. برای نسخه‌های زبانی از link rel="alternate" hreflang و برای نسخه موبایل جداگانه از rel="alternate" با ویژگی media استفاده کن.
- اگر نسخه AMP داری، برای تعیین صفحه کانونیکال و نسخه AMP دستورالعمل‌های AMP را دنبال کن.

## نقشه سایت و ریدایرکت

- برای هر صفحه یک URL کانونیکال انتخاب کن و فقط همان را در نقشه سایت بگذار. نقشه سایت راه ساده‌ای برای سایت‌های بزرگ است، اما سیگنال ضعیف‌تری از rel="canonical" است و گوگل خودش تکراری‌ها را تشخیص می‌دهد.
- وقتی می‌خواهی صفحه تکراری را کاملاً حذف کنی، از ریدایرکت دائمی استفاده کن تا به گوگل بگویی نسخه ریدایرکت‌شده نسخه ضعیف‌تری است.
- برای سریع‌ترین اثر، ریدایرکت سمت سرور (HTTP) را به روش‌های دیگر ترجیح بده.
- اگر یک صفحه از چند آدرس در دسترس است (مثل example.com/home، home.example.com و www.example.com)، یکی را به‌عنوان کانونیکال برگزین و بقیه را به آن ریدایرکت کن.

## HTTPS و سیگنال‌های ضمنی

- برای اینکه گوگل نسخه HTTPS را کانونیکال کند، از HTTP به HTTPS ریدایرکت بگذار، از HTTP به HTTPS rel="canonical" بده و در صورت امکان HSTS را پیاده‌سازی کن.
- از گواهی SSL/TLS نامعتبر یا ناهماهنگ با میزبان، وابستگی‌های ناامن (غیر از تصویر) در صفحه HTTPS، ریدایرکت HTTPS به HTTP و rel="canonical" از HTTPS به HTTP پرهیز کن، چون باعث می‌شود گوگل به‌شدت HTTP را ترجیح دهد و HSTS نمی‌تواند آن را خنثی کند.
- نسخه HTTP صفحه‌ها را به‌جای HTTPS در نقشه سایت یا حاشیه‌نویسی‌های hreflang نگذار.
- مطمئن شو گواهی SSL کل URL سایت را پوشش می‌دهد یا گواهی wildcard برای زیردامنه‌ها باشد.

## hreflang و رندر جاوااسکریپتی

- اگر از hreflang استفاده می‌کنی، صفحه کانونیکال را هم‌زبان با همان صفحه تعیین کن؛ در نبود آن، نزدیک‌ترین زبان جایگزین را انتخاب کن. این نکته برای سایت‌های فارسی و چندزبانه مهم است.
- همه نسخه‌های زبانی را با hreflang به‌صورت دوطرفه به هم متصل کن، چون گوگل URLهای عضو خوشه hreflang را برای کانونیکال ترجیح می‌دهد و صفحه‌ای که در خوشه نیست ممکن است کنار گذاشته شود.
- در رندر سمت کلاینت با JavaScript، URL کانونیکال را در HTML منبع تعیین کن و مطمئن شو جاوااسکریپت عنصر canonical را تغییر نمی‌دهد.
- اگر نمی‌توانی کانونیکال را در HTML منبع تنظیم کنی، آن را آنجا نگذار و فقط با JavaScript و به‌صورت صحیح تنظیم کن تا اطلاعات کانونیکال روشن بماند.
